# Linear issue management

Linear is the Dev Crew's source of truth for work. Use the GraphQL API:

- Endpoint: `https://api.linear.app/graphql`
- Header: `Authorization: $LINEAR_API_KEY`

The workspace and team are configured for the project (team key `BON`). Look up IDs as needed.

## Projects (grouping unit)

A product effort is a Linear **Project**, not a synthetic parent epic ticket.

- **Create project**: `mutation { projectCreate(input: { name: "...", teamIds: ["..."] }) { project { id name url } } }`
- **Link issue to project**: `mutation { issueUpdate(id: "...", input: { projectId: "..." }) { issue { identifier } } }`
- **List issues in a project**: query the project and its issues, or filter issues by `project`.

When decomposing a reviewed spec:

1. Create (or reuse) a Linear Project for the effort.
2. Create the implementation tickets.
3. Link every ticket to the Project.
4. Do **not** invent a parent "epic" ticket solely for grouping.

## Common operations

- **List issues**: `{ team(key: "BON") { issues { nodes { identifier title state { name } assignee { name } project { name } } } } }`
- **Create issue**: `mutation { issueCreate(input: { teamId: "...", title: "...", description: "...", assigneeId: "...", projectId: "..." }) { issue { identifier url } } }`
- **Move state**: look up the workflow state id first, then `issueUpdate(id: "...", input: { stateId: "..." })`.
- **Comment**: `commentCreate(input: { issueId: "...", body: "..." })`.

## Rules

- Every ticket has a clear title and a description with acceptance criteria.
- Prefer linking tickets to a Project over creating parent/child epic trees for grouping.
- When an agent finishes, it comments the result and moves the ticket state (e.g. to Done / In Review). The runtime completion hook also posts a deterministic signal.
- Prefix AI-generated comments with: `> *This was generated by AI.*`

## Anti-patterns

- Creating tickets outside the effort's Linear Project.
- Moving tickets to states the workflow does not define.
- Closing projects; closure is a human decision.
- Hardcoding API keys in commands or committed files.
